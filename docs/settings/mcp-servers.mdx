## Overview

MCP servers provide additional functionality to coding agents through standardized protocols. You can define a logical MCP server once in Vibe Kanban and assign it to one or more compatible coding agents, giving them access to specialised tools like browser automation, remote logs, Sentry, or documentation from Notion.

## Accessing MCP Server Configuration

1. Navigate to **Settings** in the Workspaces navbar
2. Click on **MCP Servers** tab
3. Add or edit a logical MCP server
4. Select the agent assignments that should receive that server

## Adding Custom MCP Servers

You can also add your own MCP servers by configuring them manually:

<Steps>
<Step title="Create the logical server">
Click **Add server**, enter the server name, and choose the transport configuration.
</Step>

<Step title="Choose assignments">
Select one or more compatible agents. Vibe Kanban writes the server into each selected agent's native MCP configuration file.

Example stdio server:
```json
{
  "command": "node",
  "args": ["/path/to/my-server.js"]
}
```
</Step>

<Step title="Save and Test">
After updating assignments:

1. Click "Save Settings" to apply changes
2. Click **Test connection** to test saved native entries
3. Review test results per server and per assigned agent

<Check>
These changes update the global configuration file for each assigned coding agent and persist even if you stop using Vibe Kanban.
</Check>
</Step>
</Steps>

## Conflicts and compatibility

## Refreshing MCP tools in an existing task

Saving or reconnecting a server updates the selected agent's native
configuration, but an agent process that was already running may still hold its
old tool registry. In the workspace toolbar, choose **Refresh MCP tools** for a
Codex session. Vibe Kanban asks Codex to reload at a safe turn boundary and then
reads Codex's next-turn server status; the request is not presented as complete
until adoption is observed. The tooltip reports each configured server's live
status and tool count.

For an executor without a proven live-reload protocol, the same toolbar location
offers **Restart agent for MCP changes**. A running turn finishes before the
replacement process starts, and the existing task and chat remain intact.

If Slack tests connected in Settings but the Codex refresh tooltip says it is
absent from the active tool registry, these are different facts: the settings
probe proved the saved endpoint from one host, while the live status proved that
the current Codex process did not adopt it. Confirm that `slack` is assigned to
Codex, refresh again, and check the worker that owns the workspace. A ready Slack
server with zero tools is also unavailable, not connected.

### Read-only Slack inventory searches

The managed Vibe Kanban Slack service exposes only read tools. Its enabled set
includes `conversations_search_messages`, conversation history/replies, channel
and user lookup, unread/saved-item reads, and bounded attachment retrieval. It
does not expose message posting, reactions, user-group mutation, or saved-item
mutation tools. Search exact hostnames as quoted terms and inspect the returned
channel, timestamp, and permalink; Slack continues to enforce the connected
identity's channel visibility.

For local generic templates, use a Slack identity with only the permissions
needed by the chosen read tools. The managed deployment keeps its Slack token in
the supervised server's credential boundary and writes only the private MCP URL
to Codex configuration.

## Shared authentication gateway

For an OAuth-protected HTTP MCP server, run **Test connection** and choose
**Connect** when authentication is required. Vibe Kanban completes OAuth once,
encrypts the upstream access and refresh tokens in its local credential store,
and replaces every matching assigned agent entry with a protected loopback
gateway URL. Agent configuration contains only that local URL and its local
capability—not the upstream bearer or refresh token.

The authentication badge distinguishes shared gateway authentication from
agent-native, explicit-header, and unauthenticated servers. **Reconnect** rotates
and replaces the shared credential. **Disconnect** invalidates the connection
for every assignment; removing one agent assignment does not disconnect the
others. Test results show the gateway and upstream boundaries separately.

If OAuth discovery reports a Cloudflare Access interactive redirect, configure
a Cloudflare Access service token when prompted. Its client ID and secret are
write-only, centrally encrypted, and sent only to the upstream service.

If Vibe Kanban finds same-name native entries with different definitions, it shows
a conflict instead of choosing one silently. Rename or delete one of the entries
before saving shared changes.

Some agents support fewer MCP transports than others. Vibe Kanban blocks an
assignment when the selected transport cannot be represented safely in that
agent's native configuration.

## Best Practices

<Tip>
**Server Selection**: Choose MCP servers that complement your coding agent's primary function. For example, use Playwright for agents focused on web development.
</Tip>

<Tip>
**Limit MCP Servers**: Avoid adding too many MCP servers to a single coding agent. Too many servers and tools will degrade the effectiveness of coding agents by overwhelming them with options.
</Tip>
