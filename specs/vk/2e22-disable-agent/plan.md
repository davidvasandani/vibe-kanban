# Implementation Plan: Disable unused agents

**Spec**: `./spec.md`
**Status**: Draft

## Technical Context
- Backend: Rust workspace. Agent profiles live in `crates/executors/src/profile.rs`
  (`ExecutorProfile`, `ExecutorConfigs`). They are persisted as an overrides
  file (`profiles.json`, `workspace_utils::assets::profiles_path()`) merged
  over the embedded `crates/executors/default_profiles.json`, and served by
  `GET/PUT /api/profiles` and `GET /api/info` (`crates/server/src/routes/config.rs`).
- Frontend: React + TypeScript in `packages/web-core` (shared by local-web
  and remote-web). Pickers read `useUserSystem().profiles`, which is
  `UserSystemInfo.executors`. Settings → Agents edits a local copy of the
  profiles JSON and saves it through `useMachineProfiles(machineClient)`.
- Types: `shared/types.ts` is generated by ts-rs from
  `crates/server/src/bin/generate_types.rs`. `ExecutorProfile` is already
  exported.
- Constraint: built-in executors can't be removed from the map
  (`ProfileError::CannotDeleteExecutor`), so disabling has to be a flag.

## Architecture & Approach

### Storage (FR-10, FR-11, FR-12)
1. `crates/executors/src/profile.rs`:
   - Add `pub disabled: bool` to `ExecutorProfile` with
     `#[serde(default, skip_serializing_if = "std::ops::Not::not")]` (see the
     `./contracts/` doc).
   - `merge_with_defaults`: an override with `disabled: true` sets it on the
     merged profile.
   - `compute_overrides`: carry `disabled` when it differs from the default,
     and keep a profile in the overrides when `disabled` is its only change.
   - `get_recommended_executor_profile`: iterate
     `recommendation_candidates()`, a new helper returning enabled agents
     only, which is unit-testable without installed CLIs.
2. Struct literals:
   - `crates/executors/src/env.rs` (test helper) and
     `crates/local-deployment/src/container.rs` get `disabled: false`.
   - `crates/worker/src/execution.rs` copies `disabled` from the
     source profile together with `recently_used_models` and
     `disabled_models`, so the dispatched snapshot stays faithful (XXIII).
3. Run `pnpm run generate-types`. `ExecutorProfile` gains
   `disabled?: boolean`.

### Shared resolver (FR-4 to FR-9, constitution XXI and L)
4. New `packages/web-core/src/shared/lib/disabledAgents.ts` is the single
   frontend definition of "disabled":
   - `isAgentDisabled(profiles, agent)`
   - `filterEnabledAgents(agents, profiles, keep)`: keeps order, and keeps
     agents in `keep`
   - `setAgentDisabled(profiles, agent, disabled)`: spreads the profile, and
     deletes the key when the agent is enabled
   - `getDisableAgentBlocker(profiles, agent, defaultAgent)`: returns
     `'default' | 'last' | null`
5. `packages/web-core/src/shared/lib/executor.ts`: add `'disabled'` to
   `RESERVED_KEYS` so `getExecutorVariantKeys` never shows it as a
   configuration.

### Settings → Agents (FR-1 to FR-3, FR-7 to FR-9)
6. `packages/web-core/src/shared/dialogs/settings/settings/AgentsSettingsSection.tsx`:
   - The Agents column dims disabled rows and shows
     `TwoColumnPickerBadge` "Disabled" (default variant). The order is
     unchanged.
   - New `AgentVisibilityCard` (in the same file, like `AgentModelsCard`)
     with a `SettingsCheckbox` "Show in agent pickers". It is locked by
     `getDisableAgentBlocker` with a reason. Changes go through `markDirty`,
     so the existing save bar, discard and drawer guard apply (X, XLII).
   - `ConfigActionsDropdown` gets an `agentDisabled` prop that disables
     "Make Default" (FR-9).
   - The existing `refreshProfileViews()` already invalidates
     `['user-system']` after a save, so every picker sees the change.
7. i18n: add `settings.agents.editor.disabled` and
   `settings.agents.visibility.*` to all seven locales under
   `packages/web-core/src/i18n/locales/*/settings.json`.

### Pickers (FR-4 to FR-6)
8. `packages/web-core/src/shared/hooks/useExecutorConfig.ts`
   (`useEffectiveExecutor`) feeds both the create-workspace and the
   new-session chat boxes:
   - The fallback chain skips disabled agents for `lastUsedConfig` and the
     config default.
   - The user's selection and the scratch draft are kept.
   - `options = filterEnabledAgents(all, profiles, [effective])`.
9. `packages/web-core/src/shared/components/tasks/AgentSelector.tsx`
   (Start review, Resolve conflicts): filter, keeping the selected agent.
10. `packages/web-core/src/shared/dialogs/settings/settings/GeneralSettingsSection.tsx`:
    - The default-agent options keep the draft default.
    - The remediation executors keep the configured remediation agent.
11. `packages/web-core/src/features/onboarding/ui/LandingPage.tsx`: filter,
    keeping the selected agent.

### Non-goal enforcement (FR-13)
There are no backend checks on execution paths. `ExecutorConfigs::get_coding_agent`
and the MCP and worker paths are untouched.

## Constitution Check
- **I / III / VI:** extends the shipped `disabled_models` machinery (same
  struct, same merge path, same save bar). No new endpoint, dependency or
  storage.
- **II:** Rust unit tests in `profile.rs`. Vitest for `disabledAgents.ts`
  and for the `useExecutorConfig` fallback rule (pure function extracted for
  testability).
- **IV:** no `@vibe/ui` change. The `web-core` containers pass filtered
  options to `CreateChatBox`/`SessionChatBox`. Both frontends are the blast
  radius, and both use the same web-core code.
- **X / XLII:** the edit lives in the section's local profiles copy until
  Save, and Discard reverts it.
- **XXI:** one resolver (`isAgentDisabled`) on the frontend and one field on
  the backend. Pickers accept the default agent (it can never be disabled
  via the UI and is kept visible regardless).
- **XXIII:** the worker snapshot carries the flag unchanged.
- **XXXVIII:** pickers are choices, not explicit lookups. The current value
  stays visible.
- **XLVIII:** new frontend code is linted by `pnpm run lint`, with no
  disables.
- **L:** this feature is the case the principle was written for.

No deviations.

## Risks & Dependencies
- **Stale picker copies re-saving profiles.** `ModelSelectorContainer` saves
  the whole profiles map on a recent-model write. It spreads each profile,
  so `disabled` survives. Settings invalidates `['user-system']` after a
  save (wiki `model-picker-preferences`).
- **A hand-edited `profiles.json` disabling every agent, or the default
  one.** Pickers keep the effective/current agent visible and fall back to
  the first agent overall if every agent is disabled, so a picker is never
  empty.
- **Locale gate:** `scripts/check-i18n.sh` fails if any locale misses a key.
