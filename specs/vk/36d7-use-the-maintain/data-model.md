# Data Model: pinned Slack MCP connector from the maintained fork

No database entities, no API DTOs, no generated TypeScript types. The feature
adds exactly two pieces of structured data.

## 1. `checksums.json` (inside the launcher tarball)

Generated by `scripts/build-release.sh` at release time; read by the launcher at
run time. Never hand-edited.

```json
{
  "name": "slack-mcp-server-vk",
  "version": "1.3.0-vk.2",
  "tag": "v1.3.0-vk.2",
  "baseUrl": "https://github.com/davidvasandani/slack-mcp-server/releases/download/v1.3.0-vk.2",
  "assets": {
    "darwin-arm64": { "file": "slack-mcp-server-darwin-arm64", "sha256": "…", "size": 0 },
    "darwin-x64":   { "file": "slack-mcp-server-darwin-amd64", "sha256": "…", "size": 0 },
    "linux-arm64":  { "file": "slack-mcp-server-linux-arm64",  "sha256": "…", "size": 0 },
    "linux-x64":    { "file": "slack-mcp-server-linux-amd64",  "sha256": "…", "size": 0 },
    "win32-arm64":  { "file": "slack-mcp-server-windows-arm64.exe", "sha256": "…", "size": 0 },
    "win32-x64":    { "file": "slack-mcp-server-windows-amd64.exe", "sha256": "…", "size": 0 }
  }
}
```

| Field | Meaning |
| --- | --- |
| `version` | launcher package version; also the cache directory segment |
| `tag` | fork release tag the binaries were built from |
| `baseUrl` | immutable release download prefix; concatenated with `assets[k].file` |
| `assets` | keyed by `${process.platform}-${process.arch}`, so lookup is a single map read |
| `sha256` | lowercase hex, enforced before the binary is cached or executed |
| `size` | expected byte count; used only to reject obviously truncated downloads early |

Invariants: exactly the six supported keys; every `sha256` 64 hex chars; `tag`
matches the tag embedded in `baseUrl`; `version` matches `package.json`.

## 2. Pin constants (`crates/executors/src/mcp_config.rs`)

| Constant | Value shape | Consumed by |
| --- | --- | --- |
| `SLACK_MCP_FORK_TAG` | `v<upstream-base>-vk.<n>` (e.g. `v1.3.0-vk.2`) | pin-shape test; docs cross-reference |
| `SLACK_MCP_LAUNCHER_SHA256` | 64 hex chars | `#[ignore]`d digest test |

These are the repository-side record of the pin. Renovate reads the tag out of
the URL in `default_mcp.json`; the `packageRule` requires that a bump refresh
the URL, both constants, and the docs version together.

## Cache layout (derived, not persisted state)

```
<cache-root>/slack-mcp-server-vk/<version>/<asset-file>
```

Version-scoped, so a new pin never collides with an old cache and rolling back
re-uses the previous entry. Downloads land in a sibling temp file and are
renamed in only after digest verification, so an interrupted download can never
be executed.
